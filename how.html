A game, built out loud.

A student asked how are video games made? The answer is one HTML file you can open from disk. This page is the time-lapse of how that file got written — by a teacher and a few long-running AI agents, over three days in September 2026.

First draft. Dates are real. The dialogue is summarized, not a transcript. Other sessions will fill in the close-ups.

The whole story, ADEPT-style

ADEPT is a way to explain a hard thing: Analogy, Diagram, Example, Plain English, then Technical. We use it here because this page is for you, not for the agents who typed the file.

Analogy
First someone wrote the recipe. Then a cook followed it, one bowl at a time, until there was dinner. Then other cooks cut a window in the kitchen wall so you could watch the stove. Then they kept rewriting the sign next to the window until a first-time visitor could follow what the stove was doing.
Diagram
Two pictures matter. The game is a factory line. The build is a short timeline. They are the same idea at two speeds.
Example
Open the game. Press X. Hold an arrow key. The rows light from the top down. That light is what every phase below was trying to make visible.
Plain English
A teacher wrote strict rules. An agent built a walkable world overnight. Other agents added a panel that shows the rules happening live, then rewrote the panel until it stopped lying to a first-time reader. Someone else pointed the classroom URL at the game.
Technical
game.html · 1,800 lines · ten numbered sections plus an optional eleventh · no build, no dependencies · PRs #2 through #7.

The two pictures

The file is one sentence, sixty times a second. Only the middle of it is allowed to change the world. 

keyboard --> INPUT --> intents --> UPDATE --> state --> RENDER --> screen
                         write      write      read

The build is that sentence, stretched across three days. Each box below is a phase. Times are Hawaii time, because that is where the classroom is.

Three agent threads

That is the honest shape. Not a dozen people. Three long chats, plus the afternoon a teacher wrote the rules.

1 · The overnight builder

Sep 1, evening. One Cursor cloud agent, following the spec step by step. Result: a playable file and the two reading guides. Pull request #2.

2 · The X-ray writers

Sep 2 into Sep 3. A run of Claude Code sessions. They cut the window, taught it to pause, made it explain itself, then rewrote five sentences that were lying. Pull requests #3, #4, #5, #7.

3 · The classroom URL

Sep 2, late. A separate Cursor agent. The school link was already live — it just opened the README. Now it opens the game. Pull request #6.

Phase 0 · Sep 1, 3:40pm

Someone writes the recipe first

Before any agent typed a game, a teacher wrote the rules. That file is PRD.md. The first line that settles every later argument:

The user is a 15-year-old reading the source, not a player.

Why that line exists: a fun game with clever code would hide the lesson. A slightly duller game you can trace in fifteen minutes is the whole point.

  • One file. No build. No internet. Microsoft Edge and Chrome.
  • Ten numbered sections, in a fixed order. Render never writes.
  • Four deliverables together: the game, a teardown, ten edits, a twelve-line README.
  • Stop at P1. Combat and sound are listed so nobody "helpfully" adds them.

Why this phase: agents wander without a spine. The overnight build was told to follow section 9 of that file, in order, and commit after each step.

Phase 1 · Sep 1, about 4:00pm · PR #1

Does a blank browser even do this?

The game did not exist yet. A short agent session checked the kitchen: Chrome 148 was installed, and a throwaway page in /tmp proved Canvas, keys, a game loop, and save/load all work from file://.

One heads-up they left for the next session: Chrome DevTools paints a red "unsafe file URL" line on every local page. That is the browser talking to itself, not a bug in the game.

Test: a six-check smoke page, movement and save/load on screen. Nothing from that page was kept — it was not a deliverable.

Phase 2 · Sep 1 evening, merged 10:32pm · PR #2

Overnight: dinner, one bowl at a time

This is the first of the three long threads. A Cursor cloud agent was pointed at the spec and told to stop at P1. It built game.html in the listed order, committing after each step — except steps 5 and 6, which are the same idea (giving an item is flipping a quest flag), so they landed together. 

1  empty file, ten banners
2  CONFIG + DATA + STATE     the world as text, nothing moving
3  LOOP + RENDER             a still map on screen
4  INPUT + UPDATE + COLLIDE  you walk; trees stop you
5+6  people, items, quests   talk, pick up, open a bridge
7  a second map              a cave, through a door
8  SAVE                      K, L, N, a "saved" notice
9  prove RENDER is pure      plus a student-proof read-through
10 TEARDOWN, CHANGE-ME, README   written against the finished file

Extra things they added because a reader would trip: a file map at the top, sandy trails to each outdoor item, and boot-time checks that name a mistyped map row instead of failing silently.

Tests they actually ran: 1,222 lines, no line over 100 characters, no banned string, all ten banners, a real-Chrome playthrough of three quests / both maps / save / reload in 35 seconds. Edge was not on the machine. Still isn't, as of this draft.

Phase 3 · Sep 2, about 2:00am · PR #3

Cut a window in the kitchen wall

Playing the game still hid the lesson. The second thread starts here: an optional eleventh section, opened with X, that shows the factory line live. Intents, a log of what just changed, the tile you face, the whole of state, the heartbeat.

The important constraint, said out loud: delete section 11, the side panel, and a few lines in the loop, and the game is exactly the same. The window is bolted on. It is not the house.

Why: a student should see the pipe while walking, not only by reading. Test: the same mechanical checks, plus a headless playthrough. The reading-guide line numbers had to be refreshed — a new section shoves every later line down.

Phase 4 · Sep 2, morning · PR #4

Freeze one heartbeat

Sixty frames a second is too fast to watch. So: P freezes the world (drawing keeps going), and . runs exactly one update. Resume does not fast-forward through a pile of leftover time — the clock throws those seconds away on purpose.

Pause is not saved. Only "is the panel open?" survives a reload. Hide the panel and the world starts again, so a frozen game can never sit there with no explanation.

How this one was staffed, roughly: a stronger model wrote the spec and judged; a cheaper model typed; the session re-ran the tools before each commit. That pattern repeats in the rest of this thread.

Phase 5 · Sep 2, afternoon into evening · docs, then PR #5

The window has to explain itself

A user test found the gap that mattered: the panel existed, and the student guide never mentioned it. Someone could do all six reads and never press X. So the guides got a "before you start" pointer, and the README grew the new keys. The game file was not touched in that hour.

Then they built a proof that the window really unbolts: a tool strips section 11 from a copy and plays the leftover game. And they taught a robot to press X, P, and . so those rules stay true after the next edit.

Evening: the panel was accurate and terse, and that was the problem. A student who did not already know the arrow could not learn it from five boxes of field names. v1.3 adds a seven-row live diagram, a one-line caption under each box, and two buttons that copy this exact moment into a question for any AI. The panel learned to scroll itself so a school laptop does not lose the game off the bottom of the screen.

Tests: four tools, all green. Playthrough 36 checks, 28 seconds, zero console lines, run three times. After stripping the X-ray, the leftover game was still 1,243 lines — byte-identical to before this evening. That is the real proof the new words stayed inside the window. Budget warning they left: 1,798 of 1,800 target lines. Anything else has to pay for itself.

Phase 6 · Sep 2 night / Sep 3 · PR #6

The classroom door was already open

Third thread. The GitHub Pages URL was already publishing the repo. It rendered the README — "download and double-click" — and never mentioned that game.html was sitting right there, playable. That is why it felt like the game was not on the web.

Fix: a tiny index.html that redirects to the game. The README's first link becomes "play it here." The spec adds one sentence: Pages is extra, not instead. The file on disk still opens with the network off.

Test: walked the live root after merge; it opened the game; Chrome console empty. They could not set the GitHub "homepage" field from that session (permission denied). Edge on a school laptop is still on the to-do list.

Phase 7 · Sep 2 afternoon / Sep 3 · PR #7

Five sentences that were lying

Back in the X-ray thread. A second look — screenshots at school resolution, one reader pretending to be fifteen, one reading as a learning-UX reviewer, none of them sharing notes. The top two findings matched. Those two were treated as certain.

  • After P, the keyboard row said you pressed p, as if that key went down the pipe. It does not. The game never sees it.
  • UPDATE lit up while the state row said nothing changed. Between steps, only two timers move, and the log hides them on purpose. The row now says "timers only."
  • An empty prompt box ate the first screenful. Hidden until you copy something.
  • A caption claimed nothing lives outside state, under a box that is visibly not state.
  • The diagram was a readout. It is now an invitation: hold an arrow, watch the rows light.

Eighteen lines went in. Eighteen comment lines came out. The file is exactly 1,800 lines, and no student-facing line number in the guides had to move.

Tests: 44 playthrough checks, 29 seconds, twice, zero console output. Still nobody has opened this in Edge. The new thing to eyeball there: the widest diagram row is 54 characters, and a fat scrollbar plus Courier New might clip it.

How they knew it worked

Agents do not get a gold star for typing. They have to show the work. Four small Node scripts live in tools/. They are for maintainers, not for you — the spec refuses a test suite as a student deliverable. Still worth knowing they exist:

  • check.mjs — line count, line length, banned words, banners, "RENDER never writes."
  • playthrough.mjs — a headless browser walks both maps, does all three quests, saves, reloads, then exercises the X-ray.
  • check-xray-removable.mjs — delete the window, the leftover game still walks.
  • check-doc-lines.mjs — the teardown still points at the right line numbers.

The five-minute playthrough the spec asked for came in around half a minute, every time they timed it.

Honest gap, repeated in every handoff: this file has not been opened in Microsoft Edge on a managed school laptop. That is the next human test, not the next agent task.
